# Working on design-claude-config

> Context for Claude when **editing this repo**, not for designers
> using the rules it ships. The rules themselves live in `rules/` and
> get installed into `~/.claude/infinum/` by `setup.sh`.

## What this repo does

Ships Infinum's Claude Code configuration into a designer's
`~/.claude/infinum/` namespace, then appends **one** `@import` line to
`~/.claude/CLAUDE.md` so the rules load every session. Non-destructive
— the user's personal config is never overwritten.

The community marketplaces (`design-team-skills`, `inclusive-design-skills`)
are added via `claude plugin marketplace add` from inside `setup.sh`.
We do **not** mirror, vendor, or copy any community plugin folders here.

## Layout

```
.
├── bin/install.js   ← npx entrypoint; thin Node shim that execs setup.sh
├── setup.sh         ← single source of truth for install logic
├── rules/           ← content shipped to ~/.claude/infinum/
│   ├── philosophy.md   → Infinum design philosophy + key terms
│   ├── workflow.md     → session start, process, AI policy, project template
│   └── design.md       → skill invocation policy, Figma rules, critique format
├── package.json     ← bin field for npx entry
└── README.md        ← human-facing docs
```

## Source-to-install mapping

| Source in this repo | Installed path | Owner | Overwritten? |
|---|---|---|---|
| `rules/philosophy.md` | `~/.claude/infinum/philosophy.md` | repo | yes |
| `rules/workflow.md` | `~/.claude/infinum/workflow.md` | repo | yes |
| `rules/design.md` | `~/.claude/infinum/design.md` | repo | yes |
| _(generated by setup.sh)_ | `~/.claude/infinum/whoami.md` | **user** | **no** (created only if missing) |
| _(generated by setup.sh)_ | `~/.claude/infinum/index.md` | repo | yes (regenerated each run) |
| _(one line appended)_ | `~/.claude/CLAUDE.md` | user | no (idempotent) |

## Rules of the road

- **Never overwrite the user's `~/.claude/CLAUDE.md`.** Only ever append
  the single marked import line. Re-runs must be idempotent.
- **Never mirror, vendor, or copy community plugin folders into this
  repo.** Reference them through `claude plugin marketplace add` in
  `setup.sh`. The community repos stay under their own maintenance.
- **Don't restate community skill descriptions in `rules/design.md`.**
  Claude already has skill names + descriptions in context once a plugin
  is installed; re-listing them is duplicate work that bit-rots on
  upstream renames. Keep `rules/design.md` to Infinum-specific policy
  (process, sequencing, opt-out defaults, phase-bound mandates).
- **`setup.sh` is the single source of truth.** `bin/install.js` is a
  thin shim — don't reimplement install logic in JS. Behavior changes
  go in `setup.sh`.
- **`whoami.md` is user-owned** — `setup.sh` creates it only if missing.
- **`index.md` is repo-owned** — `setup.sh` regenerates it every run.
- **No new files in `~/.claude/`** without first deciding who owns them
  (repo or user) and adding a row to the table above.

## Upstream switchover

The community marketplaces currently point at our forks
(`not-alpha/design-team-skills`, `not-alpha/inclusive-design-skills`).
When the contributions land upstream:

1. Update `MARKETPLACES` in `setup.sh`
2. Update marketplace references in `README.md`
3. Update marketplace names in the uninstall section

Search for `TODO(upstream)` to find every switch point.

## Testing changes

After editing `setup.sh` or `rules/*.md`:

```bash
./setup.sh
```

Then verify:
- `~/.claude/infinum/` reflects the new content
- `~/.claude/CLAUDE.md` still has exactly **one** marked Infinum import line
- `whoami.md` was preserved (if it already existed)
- A fresh Claude Code session loads the rules — try a quick design question

For the npx path specifically:

```bash
npm pack && npx -y ./design-claude-config-*.tgz
```

This simulates what `npx -y github:infinum/design-claude-config` will do
once pushed, without round-tripping through GitHub.
